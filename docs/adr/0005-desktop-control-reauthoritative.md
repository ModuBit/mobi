# ADR-0005: 桌面观看的控制权随观看流生命周期存亡，重连即归 view-only

日期：2026-09-18 · 状态：已接受

## 背景

桌面观看流（machine 的一条 RFB 透传链路）上，控制权（controlled / view-only）的权威在 hub：view-only 由 hub 在 RFB 消息边界剥除输入强制执行，UI 状态只是体验呈现。回落时机三重：观看流结束、不操作超时、用户主动退出。

问题出现在「观看流结束」这一路径上：web 端 Provider 因网络抖动自动重连时会建一条**新观看流**（hub 侧新会话，权威恒 view-only），而重连前 web 持有的「控制中」是上一条流的本地快照。曾有实现把该快照重放到新连接——UI 显示「控制中」、弹出触摸工具条，但输入被 hub 静默剥除，且无任何自愈信号。

## 决策

1. **控制权随观看流生命周期存亡**：观看流是控制权的唯一载体，流亡则控制权亡。
2. **watch 响应交付权威初值**：`desktopWatchResponseSchema` 携带 `control` 强制字段；web Provider 的每个连接代际以服务端值初始化控制权状态，禁止重放上一条流的快照。
3. **重连不自动重新授予**：重连后用户再点「接管控制」重新获得输入权——控制权只能经显式动作授予（与领域定义一致：控制权 = 观看端经显式动作获得的输入注入许可）。
4. **同一观看流内的对齐通道不变**：授予/退出 API 与 SSE `desktop-control-changed` 事件仍实时对齐（超时回落等）。

## 后果

- 「重连到新流必回 view-only」在 Provider interface 上有一条契约测试（mock watch 即可断言），不依赖跨包人肉推理。
- 用户重连后多一次「接管控制」点击——换取权限状态永不出现与服务端相反的幻觉。
- 未来若引入「跨重连恢复控制权」特性，须推翻本 ADR 并重新审视显式授予原则。
